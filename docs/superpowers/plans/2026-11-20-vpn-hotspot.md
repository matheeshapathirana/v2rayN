# VPN Hotspot Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let v2rayN (Windows WPF) run a Wi-Fi hotspot whose clients are routed through the TUN VPN (`singbox_tun`), shutting it off whenever the VPN stops.

**Architecture:** Platform-neutral logic (settings, Wi-Fi QR payload, lifecycle rules, view model) lives in `ServiceLib` behind an `IHotspotController` seam, like the existing `IWindowDialog`. The WPF project implements the seam with the WinRT `NetworkOperatorTetheringManager` (available because it targets `net10.0-windows10.0.19041.0`; `ServiceLib` targets plain `net10.0`). A `HotspotCoordinator` singleton hooks `CoreManager.CoreStop` / `LoadCore` and runs a guard loop.

**Tech Stack:** .NET 10, WPF + MaterialDesign, ReactiveUI (`[Reactive]` source generator), TUnit (`TUnit.Assertions.Should`), WinRT `Windows.Networking.NetworkOperators` / `Windows.Networking.Connectivity`.

**Spec:** `docs/superpowers/specs/2026-11-20-vpn-hotspot-design.md`

## Global Constraints

- Windows WPF app only; `v2rayN.Desktop` (Avalonia) and `v2rayN.WebAPI` must build unchanged. On those, `AppManager.Instance.HotspotController` stays `null` and every coordinator call is a no-op.
- No new NuGet packages. Do not use classic ICS (`HNetCfg.HNetShare`) — it fails with `0x80040201`.
- Password: 8–63 characters. SSID: 1–32 UTF-8 bytes. Defaults: SSID = `Environment.MachineName` (truncated to 32 bytes), password = random 12 chars from `[A-Za-z0-9]`.
- Hotspot may start only when TUN is enabled **and** the core is running **and** Windows' internet connection profile is the `singbox_tun` adapter.
- When the VPN stops (TUN off, core stopped/crashed, app exit) the hotspot stops. It never falls back to the physical connection.
- On core restart: stop the hotspot before the core stops; start it again after the new core is up, only if it was on and TUN is still enabled.
- Hotspot on/off is not restored on next app launch.
- New UI strings go in `ServiceLib/Resx/ResUI.resx` (English) **and** as properties in `ResUI.Designer.cs` (it is not regenerated by the CLI build). Other languages fall back.
- Test command: `dotnet test --project v2rayN/ServiceLib.Tests/ServiceLib.Tests.csproj` (from repo root). WPF build: `dotnet build v2rayN/v2rayN/v2rayN.csproj`.

## Review Focus

1. **Core crashes while the hotspot is on** → within ~3 s the guard stops the hotspot and shows a notice; clients must not get plain internet. (Task 2 test `Guard_WhenNotOnTun_StopsAndNotifies`.)
2. **`StartTetheringAsync` throws but the hotspot is actually On** (seen in the spike) → treated as success. (Task 4, `StartAsync` re-reads state; manual check in Task 6.)
3. **User toggles TUN off while the hotspot is on** → `LoadCore` runs with TUN disabled; hotspot stays off and the user is told why. (Task 2 test `AfterCoreStart_TunDisabled_DoesNotRestartAndNotifies`.)
4. **SSID/password with `;`, `,`, `:`, `\`, `"`** → Wi-Fi QR still scans correctly. (Task 1 test `WifiQrPayload_EscapesSpecialChars`.)
5. **Exit while the hotspot is on** → hotspot stops before the core stops. (Covered by the `CoreStop` hook; Task 2 test `BeforeCoreStop_WhenOn_StopsAndRemembers`; manual check in Task 6.)

```csharp
public enum EHotspotState { Off, Starting, On, Stopping, Unavailable }

public interface IHotspotController
{
    EHotspotState State { get; }
    int ClientCount { get; }
    Task<bool> IsInternetOnTunAsync();                  // internet profile adapter == singbox_tun
    Task<string?> StartAsync(string ssid, string password); // null = success, else error message
    Task StopAsync();
}

public sealed class HotspotCoordinator
{
    public static HotspotCoordinator Instance { get; }
    public HotspotCoordinator(Func<IHotspotController?> controller, Func<Config> config,
                              Func<bool> isCoreRunning, Action<string> notify); // for tests (ServiceLib has no InternalsVisibleTo)
    public bool IsAvailable { get; }          // controller != null
    public EHotspotState State { get; }       // controller?.State ?? Unavailable
    public int ClientCount { get; }
    public Task<string?> StartAsync();        // checks TUN enabled, core running, IsInternetOnTunAsync, then validates & starts with config.HotspotItem
    public Task StopAsync();                  // user stop: clears resume flag
    public Task BeforeCoreStopAsync();        // if On: stop, set resume flag
    public Task AfterCoreStartAsync(bool tunActive); // if resume flag: tunActive ? StartAsync : notify ResUI.HotspotStoppedTunOff; clear flag
    public Task CheckGuardAsync();            // if On and !IsInternetOnTunAsync: stop + notify ResUI.HotspotStoppedVpnDown
}
```

- Guard loop: while the hotspot is On after a successful `StartAsync`, run `CheckGuardAsync` every 3 s on a `PeriodicTimer`; cancel it on stop. The loop is not exercised by tests — tests call `CheckGuardAsync` directly.
- New resx keys: `HotspotNeedTun` = "Enable Tun and start a server before starting the hotspot", `HotspotNotOnTun` = "Windows is not routing internet through singbox_tun yet; try again in a few seconds", `HotspotStoppedTunOff` = "Hotspot stopped because Tun was turned off", `HotspotStoppedVpnDown` = "Hotspot stopped because the VPN connection went down".

### Task 4: WinRT hotspot controller (WPF)

**Files:**
- Create: `v2rayN/v2rayN/Manager/HotspotController.cs`
- Modify: `v2rayN/v2rayN/App.xaml.cs` — after `AppManager.Instance.WindowDialog = new WindowDialog();` add `AppManager.Instance.HotspotController = new HotspotController();`

**Interfaces:**
- Consumes: `IHotspotController`, `EHotspotState` (Task 2).
- Produces: `public sealed class HotspotController : IHotspotController`.

Behaviour:
- `IsInternetOnTunAsync`: `NetworkInformation.GetInternetConnectionProfile()?.NetworkAdapter?.NetworkAdapterId` equals the `InterfaceGuid` of the NIC named `singbox_tun` (`System.Net.NetworkInformation.NetworkInterface.GetAllNetworkInterfaces()`, compare `Id` as a GUID).
- `StartAsync(ssid, pass)`: get the internet profile → `NetworkOperatorTetheringManager.CreateFromConnectionProfile(profile)`; build a `NetworkOperatorTetheringAccessPointConfiguration { Ssid, Passphrase }` and `await ConfigureAccessPointAsync`; if already On, stop first (so new SSID/password take effect), then `await StartTetheringAsync()`. **If it throws, or the result status isn't `Success`, wait 2 s and re-read `TetheringOperationalState`; if it is `On`, return `null` (success)**. Otherwise log the full exception (`ex.ToString()`, including the inner exception) and return its message.
- `StopAsync`: `StopTetheringAsync()` on the cached manager; swallow and log errors.
- `State` maps `TetheringOperationalState` (On/Off/InTransition→Starting/Unknown→Off); `ClientCount` → `manager.ClientCount` (0 if none).
- Mark the class `[SupportedOSPlatform("windows10.0.19041.0")]`.
